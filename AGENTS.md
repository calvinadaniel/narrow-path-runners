## Release notes

Every pull request adds an entry to `RELEASE_NOTES.md` that records what code was changed in that PR.

- Add the entry in the same PR, at the top of the list (newest first), using the format described at the top of that file.
- Describe the change in plain language: what was added, changed, fixed or removed, which areas of the code it touches, and anything to do after merging (re-run an import, redeploy, set an environment variable). Do not paste a commit-by-commit log.
- Copy the same entry into the PR description under the "Release notes" heading from the PR template.
- Keep the entry accurate if the PR changes before it merges. Docs-only and config-only PRs get a short entry too.
